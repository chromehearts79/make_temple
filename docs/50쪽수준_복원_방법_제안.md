# 50쪽(PDF50_v5) 수준으로 전권을 복원하기 위한 방법 제안

## 요약

- **스킬로 되는 것**: 50쪽을 만들며 거친 과정과 도구를 `pdf-hwpx-layout` 스킬에 넣었다. 상자 속 상자 찾기, 상자 만들기, PDF 없이 다시 만들기, 원본 화면과 나란히 비교하기, 결과 전달이 여기에 든다. 스킬 묶음은 `pdf-hwpx-layout-skill.zip`이다.
- **스킬만으로 부족한 것**: 쪽마다 레시피를 손으로 쓰는 일, 한글에서만 할 수 있는 최종 확인, 실제 글꼴 폭을 모르는 문제가 남는다. 이번 50쪽에서도 상자를 처음에 놓쳤다가 원본 화면을 받고 나서야 모두 반영했다.
- **제안**: (A) 원본 PDF로 전 쪽 스냅숏을 한 번 만든다. (B) 그림 정보로 레시피 초안을 자동으로 만든다. (C) 사용자 Mac의 한글로 검증을 자동화한다. 권장 순서는 A → C → B다.

## 1. 지금 제공하는 스킬

| 단계 | 내용 | 도구 |
|---|---|---|
| 원본 확보 | PDF가 있으면 쪽마다 스냅숏(`pNNN.json.gz` + `pNNN.png`)을 만들어 저장소에 둔다. 이후 세션은 PDF 없이 같은 작업을 한다. PDF가 없으면 그 쪽 화면을 받는다. | `pdf_snapshot.py` |
| 디자인 목록 | 쪽 그림을 확대해 상자, 번호 상자, 칸 안 상자, 회색 농도를 먼저 적는다. 줄 속 상자 후보는 도구가 위치(앞·가운데·끝)와 색까지 뽑아 준다. | `pdf_coords.py`의 `inline_tags`, `references/box-patterns.md` |
| 만들기 | 줄 속 상자는 `boxed_line` + `tag`로, 칸 안 상자는 `nest`로 만든다. 길면 장평을 72까지 낮춰 한 줄에 맞춘다. 50쪽 레시피가 기준 예시다. | `hwpx_layout.py`, `kdn_p50.py` |
| 검사 | 원문 글줄 대조(PDF 또는 스냅숏), 원본(PDF·스냅숏·화면 그림) 옆 미리보기, 디자인 목록 항목별 대조를 한다. kordoc `validate`와 다시 읽기 점검도 쓸 수 있다. | `check_hwpx.py`, `hwpx_preview.py --pdf/--ref` |
| 한글 확인 | 사용자의 한글에서 열고 저장하고 다시 연다. 그 전까지는 "편집기 검증 전 시안"으로 표시한다. | 사용자 |
| 전달 | 결과 HWPX, 바뀐 합본, 비교 그림을 판 번호를 붙여 내려받을 수 있게 보낸다. | `merge_hwpx.py` |

**설치**
- Claude Code: 이 저장소에는 `.claude/skills/pdf-hwpx-layout/`로 이미 들어 있다. 다른 프로젝트에서 쓰려면 zip을 그 프로젝트의 `.claude/skills/`나 개인용 `~/.claude/skills/`에 푼다.
- Claude 앱: 설정의 기능(스킬) 메뉴에서 zip을 올린다.
- 실행 조건: Python 3.10 이상과 `scripts/requirements.txt`가 필요하다. 미리보기에는 Node playwright와 Chromium이 더 필요하다. Claude Code 클라우드 세션에는 미리 설치되어 있다.

**확인한 것**
- 저장소 밖에 압축을 푼 사본으로 다음을 돌렸다: 스냅숏, 좌표 추출, 50쪽 재생성(v5와 같은 결과), 스냅숏 기준 글줄 대조 110/110, 화면 비교 그림, 합치기.
- 스냅숏은 실제 PDF와 13가지 호출 결과(글자층 5종, 그림, 이미지, 쪽 크기, 글줄, 상자 후보)가 모두 같았다.

## 2. 스킬만으로 부족한 점

이번 50쪽 작업에서 실제로 부딪힌 것들이다.

1. **원본 PDF가 세션에 없었다.** 이전 결과물의 글자로 레시피를 다시 돌리는 우회로를 썼다. 스냅숏이 이 문제를 없애지만, PDF로 한 번은 만들어야 한다.
2. **쪽마다 레시피를 손으로 쓴다.** 150쪽 × 쪽당 100~300줄이다. 품질이 작업 중 주의력에 달려 있어서, 50쪽에서도 상자 속 상자를 처음에 놓쳤다.
3. **최종 판정은 한글에서만 된다.** 클라우드에는 한글과 KoPub 글꼴이 없다. 미리보기와 kordoc 그림은 근사치다. kordoc 그림은 칸 안 글을 줄바꿈하지 않는다.
4. **글꼴 폭을 모른다.** 한 줄에 넣으려고 폭을 넉넉히 잡으므로, 줄 끝 상자 앞에 몇 pt 빈칸이 생긴다.
5. **그림 속 글자와 번호는 글자층에 없다.** 번호 상자, 아이콘, 그림 속 숫자는 화면을 보고 대조해야 한다.

## 3. 제안

### A. 전 쪽 스냅숏 (바로 가능, 스킬에 포함됨)

- 원본 PDF 파일들(1~50쪽, 51~100쪽, 101~150쪽)을 한 번 올려 주시면, 전 쪽 스냅숏을 만들어 저장소에 커밋한다.
- 그 뒤로는 어느 세션에서든 PDF 없이 쪽을 고치고, 원문을 대조하고, 원본과 나란히 비교할 수 있다.
- 크기는 빽빽한 쪽 하나에 약 180KB, 쪽 그림이 약 300KB다.

### B. 그림 정보로 레시피 초안 자동 생성 (효과가 가장 큼, 개발 필요)

PDF의 그림 정보(채움·테두리 사각형, 선)와 글줄로 쪽을 "상자 나무"로 나누고, 그 나무에서 레시피 초안(.py)을 만든다. 큰 틀은 띠, 표, 카드이고 그 안에 칸이, 칸 안에 줄 속 상자가 든다. Claude는 초안을 다듬기만 한다.

- 장점: 상자가 그림 정보에서 바로 나오므로 이번처럼 놓칠 일이 줄고, 쪽당 작업량이 크게 준다.
- 바탕: 이미 있는 것을 쓴다. `work/kdn2025/kit.py`의 "열 경계 = PDF x좌표" 격자 방식, `inline_tags`, `boxed_line`이다.
- 단계:
  1. 상자 나무를 뽑고, 쪽 그림 위에 상자 테두리를 그려 확인한다.
  2. 표 격자와 병합 칸을 추론한다.
  3. 레시피 코드를 만든다.
  4. 50쪽(v5)과 19쪽 같은 대표 쪽에서 손으로 만든 결과와 비교해 검증한다.
- 한계: 그림 속 글자, 도표, 사진은 여전히 사람이 판단한다. 초안이므로 다듬는 단계는 남는다.

### C. 한글 검증 자동화 (권장, 사용자 환경 필요)

- 사용자 Mac의 Claude 데스크톱 앱(컴퓨터 사용 기능)으로, 또는 Remote Control로 이 세션에 Mac 폴더를 연결해 다음을 돌린다:
  1. 결과 HWPX를 한글로 연다.
  2. 저장하고 PDF로 내보낸다.
  3. 원본 쪽과 나란히 비교 그림을 만든다.
- 이렇게 하면 "편집기 검증 전 시안" 단계가 없어지고, 쪽 넘침과 줄 넘김을 실제 한글 기준으로 판정할 수 있다.
- 필요한 것: Mac에서 실행 중인 Claude 앱, 한글, 화면 제어 권한 승인.

### D. KoPub 글꼴 실측 (선택)

- 글꼴 파일을 작업 환경에 두면 `text_width()`의 1em 추정을 실제 글자 폭으로 바꿀 수 있다. 줄 끝 빈칸과 줄 넘김이 줄고, 미리보기도 실제에 가까워진다.
- 필요한 것: 글꼴 파일 제공, 또는 배포처 접속 허용과 사용 조건 확인.

### E. 쪽 차이 점수 (선택)

- 한글에서 내보낸 PDF와 원본 쪽 그림을 겹쳐 다른 영역을 색으로 표시한다.
- 쪽마다 점수를 매겨 전권 진행 상황과 다시 볼 쪽을 정한다. C가 있어야 의미가 크다.

### kordoc 활용 범위 (이번 비교 결과)

- `validate`(구조 검증)와 다시 읽기(읽는 순서, 글자 확인)는 검사 도구로 쓸 만하다.
- `generate`는 정해진 공문서 서식으로 다시 짠다. 50쪽이 3쪽으로 늘었고 상자 속 상자가 글로 풀려서, 원본 서식 복원에는 맞지 않는다.
- 이미지 OCR은 모델 호스트(huggingface.co)를 허용해야 쓸 수 있다. 허용하면 그림 속 글자 읽기를 보조할 수 있다.

## 4. 권장 순서

1. **A**: PDF를 올려 주시면 바로 진행한다.
2. **C**: 한글 검증 연결. Mac 쪽 준비가 되면 연결한다.
3. **B**: 초안 생성기 개발. 대표 쪽 2~3개로 먼저 검증한 뒤 전권에 적용한다.
4. **D·E**: 필요할 때 진행한다.
