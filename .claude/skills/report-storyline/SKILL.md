# 경영실적보고서 실적 스토리라인

한 지표의 실적을 "편람이 묻는 것 → 기관이 답하는 줄거리"로 짠다. 서술 문법은 지표명마다 따로 있다.
[지표별 목차](references/story-grammar.md)에서 쓰려는 지표의 `story-grammar-<지표>.md`와 원문 해부
`kdn2025-<지표>.md`를 찾아 둘 다 읽는다.

| 지표(경영관리 > 안전 및 책임경영) | 서술 문법 | 원문 해부 |
|---|---|---|
| 1. 일자리 및 균등한 기회 | [story-grammar-jobs.md](references/story-grammar-jobs.md) | [kdn2025-jobs.md](references/kdn2025-jobs.md) |
| 3. 친환경･탄소중립 | [story-grammar-eco.md](references/story-grammar-eco.md) | [kdn2025-eco.md](references/kdn2025-eco.md) |
| 4. 창업 및 경제활성화 | [story-grammar-startup.md](references/story-grammar-startup.md) | [kdn2025-startup.md](references/kdn2025-startup.md) |
| 5. 상생･협력 및 지역발전 | [story-grammar-coop.md](references/story-grammar-coop.md) | [kdn2025-coop.md](references/kdn2025-coop.md) |

목록에 없는 지표는 가장 가까운 지표의 문법으로 시작하고, 다른 점을 사용자에게 알린다.
명령은 이 스킬 폴더를 현재 디렉터리로 두고 실행한다. Python 3.10 이상과 `scripts/requirements.txt`가 필요하다.
Homebrew Python처럼 시스템 설치가 막혀 있으면 가상환경에 설치한다:
`python3 -m venv ~/.venvs/report-storyline && ~/.venvs/report-storyline/bin/pip install -r scripts/requirements.txt`
그 뒤 명령의 `python3`를 `~/.venvs/report-storyline/bin/python`으로 바꿔 쓴다.

## 작업 순서

1. **편람 확정.** 지표명, 지표정의, 세부평가내용(번호 포함), 가중치를 편람 원문 그대로 받는다. 문구는 고치지 않는다.
2. **편람 문구 분해.** 세부평가내용마다 핵심어(명사구)를 뽑아 `K1`, `K2` …를 붙인다. 열거된 대상은 하나씩,
   "노력과 성과"는 빼고 센다.
3. **자료 분류.** 사용자가 준 실적을 핵심어별로 나누고, 전년도 지적사항을 평가내용에 연결한다. 수치는 전·후 연도,
   단위, 출처와 함께 적는다. 자료에 없는 수치·수상·연속 기록은 만들지 않는다. 빈칸으로 두고 사용자에게 묻는다.
4. **줄거리 설계.** 평가내용마다 첫 과제를 설계(배경 → 목표 → 축 → 추진과제 → 성과지표)나 환류(지적 → 개선과제)로
   열고(여는 방식은 지표마다 다르다: 지표 문법 2절), 나머지 과제를 축 순서대로 실행 과제로 놓는다. 실행 과제는 장면 1~3개, 장면은 문제 → 해결 → 결과, 쪽마다
   주요성과 상자로 맺는다. 과제 제목은 세부목차만 읽어도 이야기가 이어지게 쓴다.
5. **스토리라인 작성.** [`assets/storyline-template.yaml`](assets/storyline-template.yaml)을 복사해 채운다.
   다 채운 예는 `examples/kdn2025-<지표>.yaml`이다(jobs·eco·startup·coop).
6. **점검.** `python3 scripts/storyline.py check <파일>`. 오류는 고치고, 경고는 고치거나 그대로 두는 이유를 사용자에게 알린다.
7. **초안.** `python3 scripts/storyline.py render <파일> <초안.md>`로 줄거리 지도, 세부목차, Ⅰ·Ⅱ표, 본문 초안을 만든다.
   사용자가 확인한 뒤 HWPX가 필요하면 pdf-hwpx-layout 스킬로 넘긴다.

## 점검기가 보는 것

| 규칙 | 오류·경고 |
|---|---|
| 편람 핵심어마다 맡은 과제·장면이 있다 | 오류 |
| 평가내용의 첫 과제(또는 첫 장면, 설계 블록, 평가내용 `서두`)가 설계·환류다 | 경고 |
| 설계의 축·추진과제를 뒤의 과제·장면이 회수한다, 없는 축을 가리키지 않는다 | 경고 / 오류 |
| 설계의 세부목표·성과지표를 실적으로 회수한다 | 경고 |
| 실행 장면에 왜(문제)·해결·결과가 있다 | 경고 |
| 실행 과제마다 주요성과 상자가 있고 상자에 수치가 있다 | 경고 |
| 지적사항의 회수 위치·배지·참고쪽이 맞고, Ⅰ표 수치가 참고쪽에 같은 값·같은 단위로 있다 | 오류 / 경고 |
| Ⅱ표 세 칸이 차 있고 개선성과 수치가 본문에 같은 값·같은 단위로 있다 | 경고 |
| 제목이 결과 명사로 끝나고 세부목차 한 줄에 들어간다 | 경고 |

원문 PDF가 있으면 세부목차와 대조한다: `check <파일> --toc-pdf <보고서.pdf> --toc-page <PDF 쪽>`.
점검기나 예시를 고친 뒤에는 `python3 scripts/test_storyline.py`로 규칙이 그대로 걸리는지 확인한다.

## 검증된 사례

한전KDN 2025년도 보고서 「안전 및 책임경영」 네 지표를 원문 그대로 옮겼다. 세부목차는 본보고서 전체 PDF
(`2025년도 경영실적보고서 본보고서_한전KDN.pdf`)와 대조했다. 경고는 원문 자체의 연결 약점이며 각 해부 문서 11절에 풀어 두었다.

| 예시 | 원문(인쇄쪽) | 세부목차 대조 | 점검 결과 |
|---|---|---|---|
| `kdn2025-jobs.yaml` | 27~35 | 15/15 (001-050p PDF 48쪽) | 오류 0, 경고 8 |
| `kdn2025-eco.yaml` | 41~48 | 7/7 (전체 PDF 68쪽) | 오류 0, 경고 5 |
| `kdn2025-startup.yaml` | 49~56 | 14/14 (전체 PDF 76쪽) | 오류 0, 경고 8 |
| `kdn2025-coop.yaml` | 57~66 | 13/13 (전체 PDF 86쪽) | 오류 0, 경고 13 |

2번 「안전 및 재난관리」는 아직 옮기지 않았다.
